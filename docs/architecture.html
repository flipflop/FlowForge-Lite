01

A static browser app talks to one stateless API

FlowForge Lite is a canvas for building LLM pipelines. The browser app is a folder of static files with no build step. The backend is a FastAPI service with no database, running on AWS Lambda behind the same CloudFront distribution as the static files. A run is one HTTP request whose response stays open while the server streams progress as server-sent events (SSE).

This document is a reference for people changing the code. Every name in the diagrams exists in the repository. Items we could not verify from the code are marked [TK: question].

The frontend resolves the backend URL once at load (web/config.js). In production the page is served by the same CloudFront distribution as the API, so it calls relative URLs on its own origin and the browser never makes a cross-origin request. For local development, window.FF_CONFIG.API_URL wins, then ?api= on a localhost page only, then http://localhost:8000. The local backend sets CORS from ALLOWED_ORIGINS because the page (port 8080) and the API (port 8000) are different origins.

03

Every screen is built from a few stateless parts

Components are functions from props to a DOM node, written with the html tagged template in util/html.js. The template builds elements and text nodes directly and wires events with addEventListener, so interpolated values cannot inject markup. main.js builds a skeleton of data-slot hosts and mounts pieces into them.

Node bodies share one slab, NodeCard, which owns the header, status pill, output tray and the port buttons. A node body supplies only its fields. nodes/specs.js is the single description of titles, icons and ports, so handle ids stay identical between rendering, edge pruning, tests and the backend.

Every handle id has the form <node-id>-<name>, for example llm-1-prompt. The engine strips the node-id prefix to get the input name. The last five types are UI-only today: the backend passes their first input through unchanged.

04

The canvas is about 400 lines of DOM, geometry and pointer events

services/canvas.js replaced ReactFlow. It owns pan, zoom, card positions, wires and connecting. It does not own card content (injected renderNode) or state (injected store). Ports are real button.ff-port elements, so a wire end is found by measuring the DOM instead of tracking handle coordinates.

Zoom is clamped to 0.2 to 2 (MIN_ZOOM, MAX_ZOOM in geometry.js). A drag becomes a drag after 3 px. Cards mounted after createCanvas returns get .is-entering once. A wire whose port is not yet in the DOM is skipped and appears when the port does. Pure maths (bezierPath, zoomAt, screenToCanvas, fitViewport, snap) lives in geometry.js and is unit tested.

05

State changes fan out by selector, and node cards never remount

services/store.js is a 30-line container plus the FlowForge actions. State is a plain object. Each action calls set(patch), which replaces the top-level object and notifies listeners. A subscription is a selector plus a listener, and the listener fires only when the selected slice changes by Object.is (or a custom equals such as the exported shallowEqual). Actions that touch nodes or edges return new arrays so identity comparison works.

Render once, patch through refs

A node card is built once per node id. Typing in a field calls onChange(field, value), which writes the store but does not rebuild the card, because a rebuild would drop focus and caret. Anything that changes after mount is pushed in through the handle NodeCard returns: setRun for status and output, setPorts and setWidth for the Text node. The canvas treats a changed data with the same id as "ignore, the card owns its inputs".

06

Only API keys and the theme outlive a page load, and neither reaches a database

The backend has no database; the only server-side stored data is the optional demo provider keys in SSM Parameter Store. The pipeline itself is not saved anywhere: reloading the tab clears it. Saving and loading pipelines is on the roadmap in the README.

07

A run is one fetch whose events patch cards one at a time

While runStatus is "running" the Run key becomes Stop. Stop calls abort.abort(), the pending fetch or stream read rejects with AbortError, and the catch block records "Run cancelled." Other fetch failures become "Could not reach the backend". An empty canvas short-circuits with an error before any request.

08

The backend orders nodes with Kahn, runs them in turn, and holds no state

Four modules, one direction of dependency. graph.py is pure. engine.py takes a key resolver as a callback, so tests inject fakes and never reach the network. providers.py speaks plain REST through httpx. main.py adds HTTP, CORS (local development), SSE framing and the rate limit. In production uvicorn runs inside Lambda behind the Lambda Web Adapter, and the response streams through a Function URL.

Keys, limits and failures

  • Key resolution. For each LLM node, resolve_key(provider) uses the key from api_keys if present. Otherwise it reads GEMINI_API_KEY or ANTHROPIC_API_KEY from the environment, and only then consults the rate limit.
  • Rate limit. _allow(ip) keeps a sliding one-hour window per client IP, RUNS_PER_HOUR (default 10). It counts server-key LLM calls, not whole runs. Behind CloudFront the client address comes from the CloudFront-Viewer-Address header. The window lives in the memory of one Lambda container, so it resets when the container recycles and each concurrent container has its own count. Reserved concurrency caps total spend. A shared store such as Redis is the fix if this matters (ADR 0007).
  • Origin check. CloudFront adds a secret x-origin-verify header to API requests and the backend rejects requests without it, so the Function URL cannot be called directly.
  • Server keys. Optional demo keys are read lazily from SSM Parameter Store SecureStrings. They are not in environment variables or git.
  • CORS. Not used in production (same origin). For local development ALLOWED_ORIGINS is a comma-separated list; the default * is for local use only.
  • Limits. At most 50 nodes (MAX_NODES), 1024 output tokens, a 60 s HTTP timeout per provider call, up to 3 attempts on HTTP 429 or 503 with backoff of 1.5 s doubling each time.
  • Errors. A NodeError yields node_error then run_error and ends the stream. Rate-limit refusals and missing keys surface the same way.
09

One lamp, three typefaces and five hues make the tool feel like a workbench

The design system, "Clay Workbench", is specified in docs/design.md and implemented as custom properties in web/css/tokens.css. Components never hard-code a colour, font or shadow; a unit test fails if a hex colour appears outside tokens.css in the component files. This page reuses the same tokens and fonts so the document matches the app.

  • Light source. Top-left. --rim highlights top and left edges; --slab (6 px) and --edge make the card thickness. Lifting is translateY up with a softer shadow; pressing is translateY down with an inset shadow.
  • Themes. Tokens sit on :root for light and are redefined under :root[data-theme="dark"]. Initial theme precedence: ?theme=, then localStorage ff-theme, then prefers-color-scheme. An inline script in index.html sets it before first paint.
  • Accent. Coral (--accent) is the one hot mark: LLM category, focus ring, wire hover. Green (--go) is reserved for Run.
  • Motion collapses under prefers-reduced-motion.

11

One distribution serves the site and the API, deployed by one script

Production runs as a single SAM stack. One CloudFront distribution is the only public entry point. Paths that match the API patterns go to a Lambda Function URL; everything else is a private S3 bucket read through Origin Access Control. Local development is unchanged: uvicorn main:app --reload on port 8000 and python3 -m http.server 8080 -d web.

Path patternOriginCaching
/pipelines/*, /models, /healthLambda Function URL (RESPONSE_STREAM invoke mode)disabled
everything elseprivate S3 bucketenabled; HTML revalidates, fonts are long-lived

The function is Python 3.12 on arm64. The AWS Lambda Web Adapter layer runs uvicorn and translates between Lambda and HTTP, and the Function URL streams the response so SSE works.

  • Cold starts. The first request after idle pays a container start. Measured figure: [TK: measured cold-start time].
  • Route list. CloudFront forwards /pipelines/*, /models and /health to the function; deploy.sh smoke-tests GET /health after each deploy.
  • Timeouts. The function may run for 300 s with 512 MB; reserved concurrency defaults to 5 (template parameter). CloudFront's origin read timeout is 60 s between bytes, so a single provider call that sends nothing for over a minute ends the stream; events arrive per node, which keeps normal runs well inside it.
  • The reasoning and alternatives are in ADR 0007.
12

The supply chain is this repository, and keys never rest on a server

  • No third-party frontend code. No npm, no CDN scripts, no bundler. Fonts are self-hosted under web/fonts/. There is nothing to audit but the repository (ADR 0006).
  • Keys. User keys live in sessionStorage ff-keys, which is per tab and cleared when the tab session ends. They are sent only in the body of POST /pipelines/run, used for that request, and never logged or stored by the backend (ADR 0004). They are not sent to /pipelines/parse.
  • ?api= is localhost only. On a public host the parameter is ignored, so a crafted link cannot point the app at someone else's server and collect a visitor's keys. Only the host page's own window.FF_CONFIG can override the URL there.
  • Markup injection. The html template builds nodes and text nodes, so interpolated values are text. innerHTML appears only for trusted static SVG strings: icons in components/icons.js and the zoom control glyphs. Model output is shown with textContent.
  • Same origin, no CORS. In production the page and API share one origin, so a response-headers policy can set a Content-Security-Policy with connect-src 'self'. Even a compromised page cannot send pipeline data or saved keys to another host.
  • Origin lock. The Lambda Function URL only honours requests carrying the secret x-origin-verify header that CloudFront adds. The static bucket is private and readable only through Origin Access Control.
  • Server keys. Optional demo keys sit in SSM Parameter Store as SecureStrings, read lazily by the function, never in environment variables or git. Use of them is capped per client IP, and reserved concurrency caps total spend. The per-IP counter is per container, so it is a brake, not a quota.
