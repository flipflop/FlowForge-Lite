# Deploy: CloudFront + S3 (frontend) + Lambda (API)

One SAM stack, one CloudFront distribution. The page and the API share an origin, so the
browser makes same-origin requests and needs no CORS. The decision for static hosting is in
[ADR 0007](../docs/adr/0007-static-hosting-s3-cloudfront.md).

```
browser -> CloudFront --default--------------------> private S3 bucket (OAC)
                      --/pipelines/*, /models, /health--> Lambda Function URL (FastAPI)
```

| File | Purpose |
|---|---|
| `template.yaml` | SAM template: bucket, OAC, bucket policy, response-headers policy (CSP `connect-src 'self'`), distribution with two origins, API function (python3.12, arm64, Lambda Web Adapter layer v30, response streaming, 300 s timeout, 512 MB, reserved concurrency), 14-day log group, IAM for the SSM prefix. |
| `deploy.sh` | Identity guard, tests, builds `deploy/.build/api`, `sam deploy`, `s3 sync`, invalidation, `/health` smoke test. `--static-only` skips build and stack; `--build-only` only builds the bundle. |
| `set-secrets.sh` | Prompts (no echo) and stores optional server demo keys in SSM SecureString under `SSM_PREFIX`. |
| `teardown.sh` | Empties the site bucket and deletes the stack, after confirmation. |
| `deploy.env.example` | Copy to `deploy.env` (gitignored). Account ids and profile names never go in git. |

Requires the AWS CLI, [SAM CLI](https://docs.aws.amazon.com/serverless-application-model/latest/developerguide/install-sam-cli.html), Python 3 with pip, Node (tests) and openssl.

```bash
cp deploy/deploy.env.example deploy/deploy.env   # then edit
./deploy/set-secrets.sh           # optional demo keys; without them users bring their own
./deploy/deploy.sh                # first time, or after backend/template changes
./deploy/deploy.sh --static-only  # content-only publish
```

## How the API is protected
- **Origin verification.** The Function URL is public by necessity. CloudFront adds an
  `x-origin-verify` header (the `OriginVerifySecret` parameter, generated by `deploy.sh` and kept in
  `deploy.env`); the backend returns 403 to anything without it (`ORIGIN_VERIFY_SECRET` env var,
  constant-time compare). Unset locally, so there is no check in development.
- **Per-IP rate limit** (server demo keys only) uses `CloudFront-Viewer-Address` when origin
  verification is active, otherwise the socket peer.
- **Spend cap.** `RESERVED_CONCURRENCY` (default 5) bounds parallel executions; `RUNS_PER_HOUR`
  limits demo-key LLM calls per IP.
- **Secrets.** Demo keys are SSM SecureStrings under `SSM_PREFIX`; the function gets only the prefix
  name in its environment and reads the values once per container.
- **CSP** `connect-src 'self'`: the page can only talk to its own origin.

Because CloudFront maps 403 from any origin to the app shell, a rejected origin check shows as the
page, not a JSON error; call the Function URL directly to see the raw 403.

Caching: HTML `no-cache`; CSS/JS 5 minutes (ES modules are imported without version tags);
fonts one year, immutable. API paths are never cached. `dev/` and `tests/` are not published.
